# 依赖安全基线与整改路线

核验日期：2026-07-21
核验环境：Node.js 20.18.0 / npm 10.x

## 当前审计结果

| 范围 | low | moderate | high | critical | 总计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 根工作区生产依赖（`npm audit --omit=dev`） | 2 | 14 | 28 | 0 | 44 |
| Electron 生产依赖（`cd electron && npm audit --omit=dev`） | 1 | 0 | 1 | 0 | 2 |

这不是“零漏洞”声明。当前版本没有 npm 报告的 critical 漏洞，但仍有必须持续整改的高、中风险依赖。公开部署前应结合实际暴露面、反向代理、认证策略和所启用模块做风险复核。

## 已知主要风险簇

- Next.js 14.x 的多个安全公告；npm 给出的完整修复路径涉及升级到较新的主版本，需要单独完成兼容性迁移和回归测试。
- NestJS 10 依赖树及相关 HTTP/工具链公告，需要在后端框架升级任务中集中处理。
- `nodemailer` 的完整修复涉及主版本升级，需要复测 SMTP、IMAP 与退信流程。
- `xlsx` 当前在 npm 审计数据中没有直接可用的自动修复版本；导入文件必须继续限制大小、类型与来源，并评估替代库。
- Crawlee/浏览器自动化依赖树带来的间接公告；未使用相关能力时应保持关闭，使用时应置于隔离运行环境。
- Electron 依赖树仍有 1 个 high 公告；桌面发布前必须重新审计 Electron、electron-builder 与 updater 链。

## 发布策略

1. CI 阻止新增 critical 漏洞，但不会把现存 high 风险伪装成已解决。
2. 不运行 `npm audit fix --force`：它可能跨主版本改写依赖并破坏 CRM、邮件、WhatsApp 或桌面构建链。
3. 每个主版本升级使用独立分支，至少执行后端、前端、Electron 和 OpenClaw 全套测试。
4. 对公网部署启用 HTTPS、最小端口暴露、强密码、密钥轮换、限流和备份；未使用的集成保持关闭。
5. 每次发布重新生成审计结果，并在 release notes 中公开尚未闭合的风险。

## 建议整改顺序

1. Next.js 与 React 兼容升级。
2. NestJS 与 HTTP 客户端依赖升级。
3. Nodemailer/邮件链路升级与收发回归。
4. Electron 运行时、构建器和更新链升级。
5. `xlsx` 替代方案评估与导入沙箱化。
